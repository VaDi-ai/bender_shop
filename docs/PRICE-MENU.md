# Прайс внутри Telegram-бота

Покупатель: `/start` → **ПРАЙС** → раздел. Текст и кнопки меняются в одном сообщении. **Назад** возвращает на уровень выше. Переходов в каналы нет. Все исходные категории сохранены; незаполненный раздел показывает «Прайс скоро появится».

Администратор из существующего `ADMIN_IDS`: `/start` → **Управление прайсом**, либо команда `/price_menu` в личном чате.

- **Текст прайса**: ответьте на сообщение бота своим текстом. До 3500 символов, с переносами строк и эмодзи. `-` очищает текст. Форматирование HTML/Markdown не применяется.
- **Добавить кнопку**: откройте нужный родительский раздел, нажмите кнопку и ответьте названием. В новом разделе можно добавить подразделы или заполнить текст.
- **Название**: ответьте новым названием (до 64 символов).
- **Удалить кнопку**: требуется подтверждение; удаляется также её содержимое и подразделы.
- `/cancel` отменяет текущий ввод. Отвечать нужно именно на запрос бота. Запрос действует 15 минут.
- **Посмотреть прайс** показывает результат. Вернуться в редактор можно через `/price_menu`.

Изменения становятся видны при следующем открытии раздела. Уже открытые у покупателей сообщения не обновляются рассылкой. Старые сообщения и сообщения в каналах не затрагиваются. Цены не синхронизируются и не генерируются автоматически.

## Хранение и выпуск

Дерево и тексты хранятся отдельно от БД магазина: `PRICE_MENU_FILE`, либо `${PHOTOS_DIR}/.bender-price-menu/menu.json`. На текущем Railway используется постоянный том `/data/photos`, файл `/data/photos/.bender-price-menu/menu.json`. Скрытая папка не раздаётся стандартным static middleware. Файл создаётся при первом сохранении администратором. Без настроенного постоянного пути чтение заготовок доступно, сохранение запрещено.

Сохранение атомарное; предыдущая версия остаётся в `menu.json.bak`. Ошибка записи не меняет активное меню. Повреждённый файл не заменяется пустым. Ревизия защищает от перезаписи параллельных изменений администраторов. Решение рассчитано на текущую одну реплику сервиса и один постоянный том.

Для этого выпуска `railway.toml` использует пустое действие перед запуском (`node -e "process.exit(0)"`) вместо миграций. Схема Prisma, миграции, код Mini App, магазин и зависимости не менялись. Обычные существующие фоновые и стартовые операции приложения не изменялись.
