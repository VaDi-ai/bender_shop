# PRICING-AUDIT — парсинг цен от поставщиков (как устроено / что оживлять / что дописать)

> Аудит на 2026-07-24. **Только чтение, код не менялся.** Это **флагманская живая фича**, а не рудимент
> (правка к [ADMIN-AUDIT.md](ADMIN-AUDIT.md), где помечена ошибочно). 0 строк на проде = не запускали, а не «мёртвая».
> Цель владельца: поставщики шлют прайсы 10+ раз/день → выбор лучшей цены среди поставщиков → наценка
> (на сайт одна, на Авито другая) → цена на витрине. **Самообучение без разработчика.**

## TL;DR
- **Парсер — не regex, а LLM** (`lib/ai-parser.ts`, `claude-haiku-4.5` через OpenRouter). Regex — только пред-фильтр.
- **Два пути приёма**: (A) авто — бот в группах поставщиков ловит текст; (B) ручной — админ вставляет прайс в «💰 Цены». Оба пишут `SupplierPrice`, оба зовут один парсер, оба используют `PriceAlias`.
- **Авто-путь УЖЕ подключён** (`bot/index.ts:223`), просто **не заведён ни один `Supplier`** → 0 строк. Плюс латентный баг: поставщики в **личке** молча отбрасываются (`bot/index.ts:225`).
- **`SupplierPrice`** хранит цену по каждому поставщику с `parsedAt` (свежесть), MIN считается `orderBy price asc` + фильтр 24ч (+ фоновая деактивация >24ч). Freshness есть.
- **`PriceAlias`** — самообучение частично работает: создание товара учит надёжно; «привязать к существующему» и «игнор» учат по **строке с ценой** → назавтра не сматчится (**главный баг самообучения**).
- **`MarkupRule` — БЕЗ канала**. Авито берёт ту же `Product.price`. Разных наценок сайт/Авито **нет** → нужна аддитивная схема.
- **Обратная запись есть** (L=Закупочная, M=Рекомендованная), можно замкнуть петлю, но с оговорками (env-флаг, триггер только при смене себестоимости, Авито вручную).
- **Нет** интерактивного «выбрать минимум среди N поставщиков» и **нет** персистентной очереди «не узнал» (только in-memory).

## 1. Как устроено (обзор пайплайна)
```
Поставщик присылает текст прайса
   │  (A) авто: бот в группе поставщика        (B) ручной: админ вставляет в «💰 Цены»
   ▼                                            ▼
webhooks/supplier.ts:handleSupplierMessage     bot/admin/pricing.ts:processSupplierPrice
   │   пред-фильтр (длина≥15, regex цены)          │
   ▼                                                ▼
lib/ai-parser.ts:parseSupplierMessage  ◄──── один LLM-парсер (OpenRouter, haiku)
   │  → [{model,storage,ram,color,country,simType,price,rawLine}]
   ▼
PriceAlias (точный матч) → канонический товар/вариант, либо «не узнал»
   ▼
SupplierPrice (строка на поставщика, parsedAt) ── свежесть 24ч, MIN = orderBy price asc
   ▼
наценка: MarkupRule (cost→retail) ИЛИ разовый %   → PendingVariant
   ▼
preview → apply: ProductVariant.price + costPrice + PriceChange(аудит) + PriceAlias(авто-обучение)
   ▼
(source='message') обратная запись в Google Sheet: L=cost, M=retail, O=поставщик, P=дата
   ▼
синк Sheets → ProductVariant.price → витрина      (Авито: /avito sync вручную, та же цена)
```

## 2. Ответы на 6 вопросов

### 2.1 `webhooks/supplier.ts` — формат и разбор
- **Формат: только текстовое сообщение.** Xlsx/фото/документы этот вебхук **не обрабатывает** (`supplier.ts:28`, `messageId` берётся, вложения игнорируются). Файлы xlsx идут только через ручной путь/`bot/index.ts:619` (документы) отдельно.
- **Пред-фильтры**: длина `<15` → выход (`:39`); должно «выглядеть ценой» `/\d{2,3}[.,]\d{3}|\d{4,6}\s*₽|\d{4,6}\s*р/i` (`:42`); поставщик должен существовать и быть активным (`:36`).
- **Разбор — LLM, не regex**: `lib/ai-parser.ts:59` (haiku через OpenRouter), Zod-валидация, JSON-repair при обрыве. Промпт (`:66-92`) знает: разделители тысяч (`122.000→122000`), «От 1 шт - 51 500→51500», `24/1TB→ram24/stor1TB`, флаги стран 🇭🇰, артикулы в скобках. Для `«iPhone 15 128 черный 65000»` модель/128GB/цвет/цена извлекает LLM.
- **Поставщик = chatId** (`:33`, `Supplier.chatId @unique`). Заводится в боте (`suppliers.ts:418`).
- **`handleSupplierMessage`** (`:23`) — пишет `SupplierPrice` c `supplierId/messageId/rawMessage` (`:73`), бампит `Supplier.lastPriceAt` (`:91`), шлёт админам сводку. **`findBestPrice`** (`:175`, фильтр `parsedAt≥now-24h`, `orderBy price asc`, наценка) — определён, но **в приложении не вызывается** (читатели используют свои inline-запросы). **`requestPriceFromAllSuppliers`** (`:153`) — рассылает «подскажите цену» всем активным.
- **Почему 0 строк**: подключение верное (`bot/index.ts:223`, до admin-гейта). Причина — **БД, не env**: пустая таблица `Supplier` / бота нет в реальных группах. Вторично — **поставщики в личке отбрасываются** (`bot/index.ts:225` `if private return next()` ДО `handleSupplierMessage`) и нужен `OPENROUTER_API_KEY` (иначе парсер отдаёт `[]`).

### 2.2 `PriceAlias` — маппинг «имя поставщика → наш вариант»
- Структура (`schema.prisma:547`): `alias @unique` (всегда lowercase), `productId?`, `variantId?`, `isIgnored`, `createdAt/updatedAt`.
- **Матч — только точный** (не fuzzy). Путь A: по `item.model` lowercased (`supplier.ts:57`). Путь B (`matchVariants` `pricing.ts:131`): три ключа OR — `model+storage+color`, `model`, `rawLine`.
- **Заводится из бота — да**: `/alias add … → товар` (`bot/index.ts:847`), `/alias ignore` (`:890`), `/alias remove` (`:914`), список (`:813`). Плюс авто-создание при apply и в мастере «создать новый». Из команды `/alias` — только на **товар** (не вариант), поиск товара по `contains` (неоднозначность).
- **Пополняемо** — да, и вручную, и обучением (см. §3).

### 2.3 `SupplierPrice` — по каждому поставщику + timestamp
- Структура (`schema.prisma:503`): `supplierId?`, денормализованные `supplierName/productName`, `variantId?`, `price`, `parsedAt @default(now())` (индексирован), `isActive`, `messageId`, `rawMessage`. **`createdAt`/`updatedAt` нет — свежесть держит `parsedAt`.**
- **По каждому поставщику отдельной строкой — да** (не дедуп, каждое сообщение = новые строки).
- **Timestamp для «свежих» и MIN — да**: `findBestPrice`/утренний бриф фильтруют `parsedAt≥24ч/сегодня`; фоновый sweep (`bot/scheduler.ts:87`) гасит `isActive=false` для строк >24ч; MIN = `orderBy price asc` + `isActive:true`. Наценка применяется на чтении (поставщицкая или `default_markup`=5%).
- ⚠️ **Разрыв**: ручной путь (B) пишет `supplierId=null` (только `supplierName`, `pricing.ts:760`). Поэтому вид «цены по поставщику» (`suppliers.ts:90`, фильтр по `supplierId`) для ручных строк пуст. Авто-путь (A) пишет `supplierId` корректно — но строк пока 0.

### 2.4 `MarkupRule` — наценки по каналам (сайт vs Авито)?
- Поля (`schema.prisma:644`): `minCost`, `maxCost?`, `mode(fixed|percent)`, `value`, `enabled`. **Ни поля канала, ни второго набора.** Одна ось себестоимости `[minCost,maxCost)`.
- `lib/markup-rules.ts:applyMarkupRules(cost)` — одномерно: одна себестоимость → одна розница, `roundPrice90`. **Нет канала.**
- **Авито = та же цена**: `syncPricesToAvito` (`lib/avito-sync.ts:334`) берёт `Product.price` и шлёт её же в Авито (`updateAvitoPrice`). Отдельной авито-цены/наценки **нет**.
- **Вывод: разных наценок по каналам сейчас НЕТ.** Нужна аддитивная схема (см. §5.1).

### 2.5 Обратная запись (L/M) — можно ли замкнуть автомат
- Колонки подтверждены (`sheets-sync.ts:113`, `EXPECTED_HEADERS`): **L = «Закупочная цена» (cost)**, **M = «Рекомендованная стоимость» (retail)**, O=поставщик, P=дата.
- **Два пути записи**:
  1. **в синке** (`sheets-sync.ts:890`): пишет **только M**, под флагом `MARKUP_RULES_ENABLED`, **только при изменении себестоимости** (`v.costPrice ≠ lastSyncedCostPrice`, `:788-802`).
  2. **из ручного флоу цен** (`pricing.ts:409-473`, `source==='message'`): пишет **L+M+O+P напрямую**, **без флага**, независимо от синка.
- **Замыкается ли петля**: технически да. `синк→витрина` цел. Но: (a) для авто-пересчёта в синке нужен `MARKUP_RULES_ENABLED=true`, иначе M из листа = источник истины; (b) запись в синке срабатывает только на **дельту себестоимости** — правка правил наценки сама по себе M не перезапишет (нужен принудительный пересчёт); (c) **Авито не в петле** — `/avito sync` вручную, и без схемы каналов несёт ту же цену; (d) синк-путь не штампует O/P.

### 2.6 `PriceChange` — годится как история/аудит
- Структура (`schema.prisma:460`): `variantId`, **`oldPrice`+`newPrice`**, `source(message|file|markup|manual|currency_update)`, `markup?`, `comment?`, `createdAt`, **`createdBy`** (tg id). Индексы по `variantId`, `createdAt`.
- **Годится как аудит розницы — да**: old→new, кто, когда, почему. Пишется на **каждый** подтверждённый apply (`pricing.ts:379`) + `logSecurityEvent('price_changed')`.
- Ограничение: привязан к **`ProductVariant`** (история **розницы**), не к себестоимости поставщика (та — в `SupplierPrice`). И пишется **только на ручном apply** — авто-вебхук `PriceChange` не создаёт (только копит `SupplierPrice`). Т.е. живое сообщение поставщика само цену на витрине не меняет — нужен admin-apply.

## 3. Самообучение из бота — что уже можно / что сломано
| Владелец должен САМ | Сейчас | Где | Оценка |
|---|---|---|---|
| Добавлять/править **алиасы** | ✅ да | `/alias add/ignore/remove/list` `bot/index.ts:805-940` + мастер «создать новый» | только на товар из команды; вариант — через qc-мастер |
| Добавлять **поставщиков** | ✅ да | `sup:add` мастер `suppliers.ts:204-418` (форвард из чата = авто chatId) | нет правки чата после создания; личка не ловится |
| Править **правила наценки** | ✅ да | `pricing:rules_*` `pricing.ts:1928-2079` | edit только значение, не границы; непокрытая полка → 0 наценки молча |
| Разбирать очередь **«не узнал»** и обучать | ⚠️ частично | `pricing:create_new`, `qc_*`, `create_all_bulk` `pricing.ts:1063-1420` | учит; но 2 пути учат по строке-с-ценой → не сматчится; очередь только in-memory |

**Обучение РАБОТАЕТ надёжно** (ключ алиаса = `model+storage+color`, без цены):
- «Создать новый» по одному (`qc_confirm` `:1186`) и «Все сразу» (`create_all_bulk` `:1398`) — создают товар+вариант и алиас.

**Обучение СЛОМАНО / ненадёжно** (главные дефекты):
- **`qc_link` (привязать к существующему) и `qc_ignore` кладут алиас по `rawLine`** (`:1319`, `:1253`) — а `rawLine` содержит **цену**. Прайсы меняются каждый день → строка другая → назавтра не сматчится. При этом бот обещает «сматчится автоматически» (`:1326`) — **обещание ложное**. Это **самый крупный баг самообучения**.
- **Apply-алиас** (`:396`) кладётся по `productName` (наше имя), а `matchVariants` ищет по словам поставщика → совпадает редко.
- **Нет персистентной очереди «не узнал»**: `unmatched` живёт в in-memory `Map`; отмена/рестарт = потеря. Нельзя «разберу позже».
- **Нет мульти-поставщицкого «выбрать минимум»**: только «← лучшая» для показа (`suppliers.ts:169`) и `Math.min` в синке (бэкенд). Флоу обрабатывает **одно** сообщение за раз, агрегатора последних N поставщиков нет.

## 4. Что «оживлять» (чтобы авто-путь заработал, без нового кода)
1. **Завести `Supplier` из бота** (`🏭 Поставщики → Добавить`) для каждой реальной группы поставщика, добавить бота в эти группы. Это снимает «0 строк».
2. **Проверить `OPENROUTER_API_KEY`** на проде (без него парсер тихо отдаёт `[]`).
3. **Учесть баг лички**: поставщики в личных чатах сейчас отбрасываются (`bot/index.ts:225`) — либо использовать только группы/каналы, либо чинить (см. §5).

## 5. Что дописать (аддитивно, с миграцией+снапшотом)
### 5.1 Наценки по каналам (сайт vs Авито) — главный пробел схемы
Минимально и аддитивно:
- `enum PricingChannel { website avito }` + `channel PricingChannel @default(website)` на `MarkupRule`; индекс `@@index([channel, enabled, minCost])`. `loadRules(channel)` + валидация покрытия **на канал**.
- `avitoPrice Decimal? @db.Decimal(12,2)` на `ProductVariant` (хранить вторую посчитанную цену). Синк считает `price` по website-правилам и `avitoPrice` по avito-правилам; `syncPricesToAvito` шлёт `avitoPrice ?? price`.
- Всё nullable/`@default` → применяется `prisma db push` (как `pdnConsentAt`).

### 5.2 Починить самообучение (код, без схемы)
- **Ключ алиаса всегда по `model+storage+color` (без цены)**, а не по `rawLine`, в `qc_link`/`qc_ignore`/apply-алиасе. Это чинит «назавтра не сматчится».
- В `matchVariants` убрать сравнение по `rawLine` как ключ алиаса (он с ценой) — оставить нормализованный `model[+storage+color]`.

### 5.3 Персистентная очередь «не узнал» (схема + UI)
- Модель `UnmatchedPrice { supplierId?, rawLine, parsedFields Json, price, status(pending|resolved|ignored), createdAt }` → бот-раздел «Очередь распознавания»: создать товар / привязать / игнор / отложить. Резолв пишет алиас (по нормализованному ключу).

### 5.4 Мульти-поставщицкий выбор минимума (UI поверх существующих данных)
- Раздел «Лучшие цены»: агрегировать свежие `SupplierPrice` (24ч, `isActive`) по товару → MIN cost по поставщикам → наценка(канал) → preview → apply батчем. Данные уже есть; нужен агрегирующий UI. Предусловие — заполнять `supplierId` и в ручном пути (`pricing.ts:760`), сейчас `null`.

### 5.5 Замкнуть автоматизацию до конца
- Флаг `MARKUP_RULES_ENABLED=true` на проде.
- Принудительный пересчёт M при **правке правил наценки** (не только при дельте себестоимости).
- Чейнить `syncPricesToAvito` после синка/после apply (или в расписание) — hands-free до Авито (после §5.1).

## 6. План автоматизации + самообучения (петля без ручных касаний)
```
1. Поставщики заведены (§4) → бот ловит прайсы 10+/день (Path A) → SupplierPrice (свежесть 24ч).
2. Матч по PriceAlias (нормализованный ключ, §5.2). Не узнал → очередь «не узнал» (§5.3).
3. Владелец из бота разбирает очередь: создать/привязать/игнор → пишется алиас → в следующий раз авто.
4. «Лучшие цены» (§5.4): MIN cost по поставщикам → наценка по КАНАЛУ (§5.1: сайт и Авито разные) →
   preview → apply → ProductVariant.price(+avitoPrice) + PriceChange(аудит).
5. Обратная запись L/M(+O/P) в Google Sheet (уже есть) → синк → витрина.
6. syncPricesToAvito чейнится (§5.5) → Авито получает свою цену.
```
Самообучение = шаги 2–3 с нормализованным ключом: каждый разбор «не узнал» уменьшает будущую ручную работу.

## 7. Узкие места / риски
- **N+1 в матче**: `matchVariants` — по запросу алиаса+товара на строку, последовательно (`pricing.ts:128-235`) → медленно на больших прайсах.
- **Непокрытая полка наценки → 0 наценки молча** (`markup-rules.ts:50`) — товар уедет по себестоимости. Валидация только предупреждает.
- **`supplierId=null` в ручном пути** → «цены по поставщику» и чистое сравнение поставщиков не работают.
- **`rawLine`-ключ алиаса** — ложное обещание авто-матча (главный дефект обучения).
- **Личка поставщиков** отбрасывается до обработки.
- **LLM-зависимость**: парсинг завязан на OpenRouter/haiku (стоимость, латентность, доступность ключа). Нет regex-фолбэка.
- **Авито = та же цена** до §5.1 — разные наценки по каналам невозможны на текущей схеме.

### Итог: как устроено / что оживлять / что дописать
- **Как устроено**: LLM-парсинг текстовых прайсов → `SupplierPrice`(свежесть) → alias-матч → наценка(`MarkupRule`) → apply(`PriceChange`+alias-обучение) → writeback в Sheet(L/M) → синк → витрина. Авто-путь подключён.
- **Оживить (без кода)**: завести поставщиков в боте + `OPENROUTER_API_KEY` (+ учесть личку) → авто-приём заработает.
- **Дописать**: (1) каналы наценок сайт/Авито — аддитивная схема; (2) починить ключ алиаса (rawLine→нормализованный) — главный фикс самообучения; (3) персистентная очередь «не узнал»; (4) мульти-поставщицкий выбор минимума; (5) замкнуть авто-петлю (флаг + пересчёт при правке правил + чейн Авито).
