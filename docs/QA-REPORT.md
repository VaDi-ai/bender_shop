# QA-отчёт по проду bendershop.store/shop

**Дата:** 26.07.2026
**Метод:** живой прод (HTML прода идентичен `webapp/index.html` в репо), headless Chrome 150 через CDP (эмуляция 390×844 touch), curl по API, логи Railway. Код не правился.

Сводка: 3 бага ломают базовые сценарии (🔴), 4 мешают (🟠), 6 косметики/гигиены (🟡). Логи Railway чистые — ни 5xx, ни крашей; все «молчаливые» поломки живут на фронте.

---

## 🔴 Ломает

### 1. Весь нижний таббар не кликается — тапы съедает невидимая кнопка закрытой модалки товара

- **Где:** все 5 пунктов таббара (`#tabbar`, z-index 60) на любом экране, пока модалка товара закрыта (т.е. почти всегда).
- **Механика:** `.product-modal` закрыта через `opacity:0; pointer-events:none` (строка ~525), но правило `#modalAddBtn { pointer-events: all }` (строка 680) по специфичности перебивает и `pointer-events:none` контейнера, и `.box-button.disabled`. Невидимый футер модалки (z-index 8000) постоянно висит над нижними ~50px вьюпорта.
- **Доказательство:** `document.elementFromPoint()` в центре каждой из 5 кнопок таббара возвращает `#modalAddBtn` внутри закрытого `#productModal`. Реальный CDP-тап по «Акции» не делает ничего; после `productModal.style.display='none'` тот же тап переключает таб.
- **Воспроизведение:** открыть /shop → тапнуть любой пункт таббара → ничего не происходит.
- **Задето заодно:** нижняя половина кнопки «ОФОРМИТЬ» в корзине (z-index корзины 600 < 8000): когда кнопка прижата к низу экрана, тап по её центру/низу попадает в `modalAddBtn` (hit-test: верх кнопки y≈778 — кликается, y≈797 и ниже — нет). Пользователь должен попасть в верхнюю треть кнопки.
- **Примечание для фикса:** `pointer-events:all` на `#modalAddBtn` добавлен намеренно — чтобы тап по disabled-кнопке показывал подсказку «Выберите вариант». Убирать нельзя, нужно скоупить, например `.product-modal.open #modalAddBtn { pointer-events: all }`.

### 2. Поиск с «Главной» выглядит мёртвым — результаты рендерятся в скрытый экран каталога

- **Где:** хедер → лупа → ввод запроса, находясь на табе «Главная» (стартовый экран).
- **Что происходит:** ввод «iphone» находит 5 товаров и рендерит их в `#grid`, но `#grid` живёт внутри `#catalogView`, который остаётся `view-off` (display:none). `homeView` продолжает показываться — на экране ничего не меняется. Enter делает `scrollIntoView` на скрытый элемент — тоже ничего.
- **Причина:** обработчик поиска (`initSearch`, ~строка 3405) вызывает `renderGrid()`, но не `switchTab('catalog')`.
- **Воспроизведение:** /shop → лупа → набрать «iphone» → визуально ноль реакции (на табе «Каталог» тот же поиск работает: заголовок «Результаты», карточки, «Сбросить»).

### 3. Категории бургер-меню не переключают экран — с «Главной» клик выглядит мёртвым

- **Где:** хедер → ☰ → «КАТЕГОРИИ» → любой пункт (AIRPODS, IPHONE, …) и «ВСЕ ТОВАРЫ».
- **Что происходит:** `selectCategory()` (строка ~2139) ставит `activeCat`, обновляет скрытый каталог и делает `scrollIntoView` на скрытый `#catalog` — но не вызывает `switchTab('catalog')`. Меню закрывается, пользователь остаётся на «Главной» без какой-либо реакции.
- **Проверено live:** после клика по AIRPODS: `activeCat='AirPods'`, `homeVisible=true`, `catalogVisible=false`, активный таб — `home`.
- **Воспроизведение:** /shop (таб «Главная») → ☰ → КАТЕГОРИИ → IPHONE → меню закрылось, экран не изменился.

## 🟠 Мешает

### 4. `filter_line` отклоняется трекингом — аналитика дрилл-дауна теряется (подтверждено)

- **Где:** POST `/api/track` при каждом клике по линейке в каталоге (`selectLine`, строка 2048).
- **Причина:** `ALLOWED_EVENT_TYPES` в `api/server.ts:344` не содержит `filter_line` (есть `filter_brand`, `filter_category`).
- **Подтверждение live:** клик по линейке «iPhone» → `POST /api/track 400`; curl `{"type":"filter_line"}` → `{"error":"invalid type"} [400]`, `filter_brand` → `{"ok":true} [200]`.
- **Эффект:** консоль засоряется 400-ми, вся аналитика по выбору линеек не пишется.

### 5. CSP блокирует Google Fonts — весь магазин рендерится без фирменных шрифтов

- **Где:** каждая загрузка /shop.
- **Причина:** страница подключает Onest + JetBrains Mono с `fonts.googleapis.com`, а серверный CSP (helmet, `api/server.ts`) задаёт `style-src 'self' 'unsafe-inline'` и `font-src 'self' data:` — ни `fonts.googleapis.com`, ни `fonts.gstatic.com` не разрешены. Console error «violates style-src» на каждой загрузке; вся типографика (логотип, цены, кнопки «ВЗЯТЬ У БЕНДЕРА») падает в системный fallback.
- **Фикс на выбор:** добавить хосты в CSP или self-host шрифты (второе — быстрее и без внешней зависимости).

### 6. Имя товара в корзине — сырая конкатенация варианта с дублями

- **Где:** корзина, а также `items[].name` уходящее в заказ.
- **Пример live:** «Iphone 17 (eSIM / iPhone 17 256GB Black (Индия) / Black / 256GB / Индия)» — цвет, память и регион повторяются дважды, внутрь попало полное имя варианта из таблицы.
- **Эффект:** нечитаемая корзина на узком экране, такой же текст в уведомлении о заказе в CRM.

### 7. Дубли чипов атрибутов из-за регистра в данных: «eSIM» и «eSim»

- **Где:** модалка iPhone 17 → группа SIM: два чипа «eSIM» и «eSim» (это разные варианты из листа).
- **Эффект:** пользователь видит два «одинаковых» варианта; выбор «не того» меняет цену/наличие. Это данные листа (или нормализация синка), не фронт.
- **Рядом (лог Railway, известный WARN):** 39 товаров без атрибута «Цвет» (OnePlus/Honor/JBL/Xiaomi…) — сейчас невидимы на витрине (латентные дубли Phase 2), но починка данных обе проблемы закроет по одному пути.

## 🟡 Косметика / гигиена

### 8. Таб «Корзина» в таббаре никогда не подсвечивается активным
`switchTab('cart')` открывает боковую панель и делает `return` до обновления подсветки (строка 3598) — иконка корзины не активируется, остаётся подсвечен предыдущий таб. Поведение «корзина поверх экрана» — ок, но без активного состояния тап выглядит полусработавшим (учитывая баг №1 — сейчас до этого кода тап вообще не доходит).

### 9. Дробные копейки в комиссии эквайринга
Оплата картой: «Комиссия +15 706,6 ₽», «ИТОГО 127 896,6 ₽». `totalWithFee()` не округляет (×1.14). Стоит округлить до рубля (и решить, в какую сторону).

### 10. ReferenceError на каждой загрузке: `handleProductPhotoError is not defined`
`<img id="modalCarouselImg" src="" onerror="handleProductPhotoError(this)">` (строка 1210) — пустой `src` триггерит onerror при парсинге, до объявления функции в скрипте. Шум в консоли/Sentry. Лечится `src`-заглушкой или снятием атрибута src в разметке.

### 11. favicon.ico — 404
Каждая загрузка страницы в браузере тянет `/favicon.ico` → 404 (в логах network-error). Положить иконку в `public/`.

### 12. Бегущая строка в проде: «Сайт в разработке. Скоро доступен к оформлению заказов»
Это значение настройки `marquee` (`/api/settings?key=marquee`). Магазин уже принимает заказы — текст выглядит устаревшим. Не код — поменять значение настройки.

### 13. Подсказка «Выберите вариант» скрыта до клика
При открытой модалке с невыбранными атрибутами hint скрыт и появляется только после тапа по disabled-кнопке. Задумано так (shake + hint), но в паре с багом №1 стоит перепроверить после фикса. Наблюдение, не дефект.

## Что проверено и работает

- **Хедер:** лупа открывает/закрывает строку поиска; «?» открывает модалку «ПОМОЩЬ» (контент есть); корзина открывает панель; ☰ открывает меню, аккордеон «КАТЕГОРИИ» раскрывается, крестики/оверлей закрывают.
- **Таббар (после нейтрализации бага №1):** все 5 экранов переключаются, «Акции» — осознанная заглушка «Акции скоро» с рабочей кнопкой «На главную».
- **Главная:** маркиза грузится, hero-слайдер (2 слайда, точки/автопрокрутка), «Новинки» (10), «Бренды», «Хиты» с рабочими табами Хит/Советуем/Новинка, блок Apple с табами линеек. Стрелки «›» и карточка бренда корректно уводят в каталог (они вызывают `switchTab` — в отличие от бургера и поиска).
- **Каталог:** дрилл-даун линейки → модели → модалка; хлебные крошки кликабельны; чипы брендов; сортировка.
- **Карточка:** фото/карусель, выбор атрибутов активирует цену и кнопку, «ВЗЯТЬ У БЕНДЕРА» кладёт в корзину с тостом.
- **Корзина:** список, +/− количество, пересчёт, самовывоз/доставка (поле адреса появляется), способы оплаты, комиссия 14% показывается/скрывается, чекбокс согласия управляет кнопкой, клиентская валидация ФИО/телефона/адреса срабатывает (заказ при пустой форме не отправляется).
- **Кабинет без Telegram:** корректные 401-ветки («Откройте магазин из Telegram», «Войдите через Telegram»), маска даты рождения работает, сохранение профиля без авторизации даёт понятную ошибку. Проверка изнутри Telegram (initData) в этом прогоне не выполнялась — headless-браузер не даёт валидную подпись.
- **API (curl):** products/categories/hero-banners/settings/trends/cache-version/health — все 200; `/api/orders` с мусором → 400 с внятной ошибкой; `/api/profile` с поддельным initData → 401 «Неверная подпись».
- **Логи Railway:** без ошибок и 5xx; Sheets-синк каждый час (146 товаров, errors=0), Avito-бот живой.
