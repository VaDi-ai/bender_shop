# Политика порядка в репозитории

Цель — чтобы после каждой задачи в Git оставались только файлы, необходимые для работы, сборки, тестирования, деплоя или восстановления проекта.

## Что можно хранить в Git

- исходники `api/`, `bot/`, `lib/`, `webapp/`, `webhooks/`;
- Prisma-схему и миграции в `prisma/`;
- тесты в `tests/`;
- воспроизводимые утилиты в `scripts/`;
- проектную документацию в `README.md`, `docs/` и `files/`;
- конфигурацию проекта и CI;
- небольшие проверенные отчёты и rollback-снапшоты, если они нужны для аудита и их назначение понятно.

## Что не должно попадать в Git

- `.env*`, `.secrets/`, ключи и service-account-файлы;
- `backups/`, дампы базы и данные клиентов;
- `node_modules/`, `dist/`, `generated/` и прочие результаты сборки;
- локальные фото и папки подготовки фото (`Foto/`, `R/`, `R-final/`, `staging-*` и подобные);
- выгрузки и временные результаты (`*.csv`, `*.zip`, `*.log`, рабочие `*.xlsx`);
- QA-скриншоты, Playwright-артефакты, debug-файлы и временные скрипты.

Исключение — только если файл действительно является частью продукта или воспроизводимого процесса. Такое исключение нужно оставить в понятном месте и описать рядом с ним.

## Рабочий цикл

1. В начале проверить `git status --short --branch` и не затереть чужие изменения.
2. Все временные выгрузки, фото и результаты QA складывать вне репозитория в карантин `repo-cleanup-quarantine-YYYY-MM-DD`. Карантин нужен для восстановления; удаление из него выполняется отдельно после проверки.
3. Перед завершением убрать временные файлы, проверить `.gitignore` и оставить только нужные результаты.
4. Запустить проверки по затронутой области. Для общего контроля выполнить:

   ```bash
   npm run check:hygiene
   git diff --check
   git status --short --branch
   ```

5. В staged-набор добавлять файлы явно. Не использовать `git add -A`.
6. Перед коммитом убедиться, что нет строк `??`, запрещённых артефактов и секретов. Если staged-файл неочевиден — не добавлять его до выяснения назначения.
7. После коммита снова проверить состояние ветки. В конце задачи рабочее дерево должно быть чистым или иметь явно объяснённые изменения текущей задачи.

## Контроль

`npm run check:hygiene` проверяет:

- отсутствие неигнорируемых неотслеживаемых файлов;
- отсутствие запрещённых артефактов среди отслеживаемых файлов;
- отсутствие локальных QA/фото/лог-артефактов даже среди игнорируемых файлов;
- наличие `.env.example` вместо реальных окружений.

Проверка подключена к CI. Если она падает, сначала нужно убрать артефакты или документировать осознанное исключение, а не отключать проверку.

## Правило для новых инструментов

Новый скрипт добавляется только если он воспроизводим, имеет понятное назначение и не создаёт мусор в корне проекта. Его временные результаты должны попадать в игнорируемую папку или во внешний карантин. После выполнения скрипта его логи, выгрузки и скриншоты убираются.
