## ФАЗА 1 — Фикс остатков (нули не гасятся)

### Root cause
Витрина корректна: `/api/products` (api/server.ts ~656) гейтит `isAvailable:true` + `variants.some(quantity>0 && inStock)`. Баг в синке `lib/sheets-sync.ts` — 0 из таблицы не доезжает до БД:
1. Заголовок наличия ищется по `includes('В наличие')` (EXPECTED_HEADERS.quantity, ~132). Не ловит грамотные варианты («В наличии», «Наличие», «Остаток»). Не найдя — падает на позиционный fallback idx 13, который из-за лишней колонки «Категория» (idx 2) промахивается.
2. `parseRow` (~216–221): пустое/нечисловое наличие → `DEFAULT_STOCK_QTY=3` → `isAvailable = 3>0 = true`.

### Правки (`lib/sheets-sync.ts`)
1. Расширить синонимы наличия до стемов, матчинг по нормализованному (trim+lower) вхождению:
   ```
   quantity: ['налич', 'остаток', 'кол-во', 'количество', 'qty', 'stock']
   ```
   Стем `налич` ловит и «В наличии», и «Наличие». `остаток` ловит «Остаток».
2. `parseRow`: пустое/нечисловое наличие → `quantity = 0`. `DEFAULT_STOCK_QTY` оставить только явным опт-ином для сидинга (по умолчанию поведение = 0). Пример целевой логики:
   ```ts
   const qtyRaw = col(row, COL.quantity)
   let quantity = 0                      // было: DEFAULT_QTY
   if (qtyRaw !== '') {
     const q = parseInt(qtyRaw, 10)
     if (!isNaN(q)) quantity = q         // '0'→0, '5'→5, 'нет'/'-'→0
   }
   ```
3. Само-диагностика: при матче наличия через позиционный fallback — `log.warn('[sync] quantity column resolved via positional fallback', { headers })`. Плюс лог-счётчик строк, где наличие было пустым/нечисловым.

### Тесты (tests/…sheets-sync)
- header `'В наличии'` → маппится в колонку наличия (не fallback).
- header `'Остаток'` → маппится.
- `qtyRaw=''` → 0; `'0'`→0; `'нет'`→0; `'-'`→0; `'5'`→5.
- регресс: `mapHeaders` по-прежнему отдаёт `category=3` (Общая категория), `line` см. Фазу 2.

### Приёмка / проверка
- Прогнать sync на копии/стейджинге. Позиция с 0 в таблице **исчезает** из `/api/products`.
- В логах видно, ловится ли колонка наличия по имени (не fallback).

### Откат
Схему не трогаем. Откат = revert коммита. Бэкап БД перед прогоном sync (sync перезаписывает остатки).

## ФАЗА 2 — Таксономия: бренд → линейка → модель

### Идея
Иерархия почти вся в данных. Мастер-таблица (подтверждено тестами `tests/integration/sheets-sync.test.ts`):
`Бренд(1) · Категория(2) · Общая категория(3) · Название модели(4) · Цвет(5) · Память(6) …`
- **бренд** = `Product.brand` — есть.
- **линейка** = колонка **«Категория» (idx 2)** — читается синком, но выбрасывается. Это iPhone / MacBook / Galaxy S.
- **модель** = `Product.name` (из «Название модели», группировка `extractProductName`) — есть.
- **варианты** (цвет/память) = `ProductVariant` — есть.

Подход минимального риска: **линейку кладём отдельным полем на Product**, «Общую категорию» и сущность `Category` НЕ репокапим (Avito-safe). Навигацию строим на фронте из `allProducts` по `brand → line → sortOrder`.

### 2.1 Prisma (`prisma/schema.prisma`)
Добавить в `Product`:
```prisma
line       String?   // линейка бренда: iPhone, MacBook, Galaxy S (из колонки «Категория» idx 2)
sortOrder  Int  @default(0)   // порядок модели внутри линейки (из «Порядок», 1 = верх)
```
Индекс: `@@index([brand, line])`.
Миграция: `prisma migrate` + бэкап БД до. `categoryId`/`Category` (общая категория) не трогаем.

### 2.2 Sync (`lib/sheets-sync.ts`)
1. Новые маппинги колонок (EXPECTED_HEADERS), fallback-индексы в скобках:
   ```
   line:      ['Категория']            // idx 2 — ВАЖНО: 'Категория', НЕ 'Общая категория'
   sortOrder: ['Порядок','Order','Sort'] // новая колонка в таблице
   ```
   - `line` через `includes('категория')` даёт первый матч = idx 2 (idx 3 — «Общая категория» — не содержит «категория»? содержит! но findIndex вернёт первый = idx2). Проверь тестом, что `line=2` и `category=3` разъезжаются. Fallback `line` = 2.
   - `sortOrder`: если заголовок не найден — деградация в порядок строк листа (`i+1`), чтобы не падать.
2. `SheetRow` + `parseRow`: добавить `line: col(row, COL.line)` и `order` (parseInt «Порядок», пусто→по строке).
3. Группа модели (`extractProductName`+…): проставить на Product `line = group.line` (берём из первой строки группы) и `sortOrder = group.order`. При пустой `line` → фолбэк `line = row.category` (общая) или `'Другое'`.
4. `category` (общая) продолжает работать как раньше — не ломать.

Тесты: `line=2`/`category=3` разъезжаются; `sortOrder` читается; пустой «Порядок» → строковый порядок.

### 2.3 API (`api/server.ts`)
Минимально: в `/api/products` (payload, ~695) добавить в ответ:
```ts
line: p.line ?? null,
sortOrder: p.sortOrder,
```
(и `line`, `sortOrder` в `select`). `/api/categories`, `/api/brands` не обязательны к правке — навигация считается на фронте. `?category=` фильтр оставить как есть.

### 2.4 Webapp (`webapp/index.html`) — главный визуал, портируем мокап
Референс: `bender_catalog_mockup.html` (скин один-в-один: `--bg #0a0a0a`, `--surface #1c1c1e`, `--accent #a8ff3e`, JetBrains Mono, глоу). Заменяем текущие два плоских фильтра (бренд-плитки + таб-бар общих категорий) на **дрилл-даун**:

**Уровни:**
- **Бренд** — верхний чип-фильтр, горизонтальная прокрутка (свайп/drag). Порядок брендов: обновить существующий массив `BRAND_POPULARITY` под нужный (Apple, Samsung, Dyson, Garmin, …, «Прочее» последним). (Позже можно вынести в данные — не сейчас.)
- **Линейка** — сетка **фото-карточек** (не чипсы). Строится из `allProducts`: группировка по `line` в рамках активного бренда. Порядок линеек = по `min(sortOrder)` их моделей (линейка с моделью №1 идёт первой). Карточка: обложка + `«{brand} {line}»` + сабтайтл (кол-во моделей). Обложка = см. 2.5.
- **Модель** — сетка фото-карточек. Группировка `allProducts` по `line`, сортировка по `sortOrder` ASC (1 = верх; пусто → в конец, стабильно). Карточка: фото товара + имя + цена «от …». Клик → существующая карточка/модалка товара.

**Хлебные крошки:** Главная — Каталог — {Бренд} — {Линейка}. Клик по бренду в крошках → назад на уровень линеек.

**Выкинуть:** хардкод-мапу `CATEGORY_IMAGES` (~1860) и зависимость от `/public/categories/*.webp` как обложек линеек. (Оставить `no-photo` фолбэк.)

### 2.5 Обложка линейки (фото из товаров, client-side)
Считать на фронте при рендере карточек линеек, переиспользуя существующие хелперы `resolvePhoto` / `isNoPhoto` (webapp ~1404, 1504–1517):
```
обложка(линейка) =
  фото самой новой модели линейки (min sortOrder), у которой есть реальное фото (не no-photo)
  → фолбэк: любой товар линейки с реальным фото
  → фолбэк: no-photo плейсхолдер
```
`allProducts` уже in-stock-only, так что обложка автоматически «живая» и честная. Фото модели-карточки = штатный резолвер товара (variant.photos → photoUrl → photos[0] → no-photo), ничего нового.
