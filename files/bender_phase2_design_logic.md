# Bender Shop — Phase 2: дизайн-логика фильтрации (для дизайна + CC)

Референс визуала: `bender_catalog_mockup.html` (скин один-в-один: `#0a0a0a` фон, `#1c1c1e` карточки, `#a8ff3e` неон-акцент, JetBrains Mono, глоу).

## 1. Три уровня навигации (дрилл-даун)

```
БРЕНД → ЛИНЕЙКА → МОДЕЛЬ → (карточка товара с вариантами)
```

- **Бренд** — верхний горизонтально-прокручиваемый чип-фильтр (свайп/drag). Apple, Samsung, Dyson, Garmin, … , «Прочее» последним. Мультибренд подтверждён — не Apple-only.
- **Линейка** — сетка **фото-карточек** (iPhone, MacBook, Galaxy S, Dyson Фен…). Клик по бренду → сетка линеек этого бренда.
- **Модель** — сетка **фото-карточек** (iPhone 17 Pro Max…). Клик по линейке → сетка моделей, отсортированных новые-сверху.
- Клик по модели → существующая карточка/модалка товара с вариантами (цвет/память).

## 2. Источник данных (из таблицы, ничего не хардкодить)

| Уровень | Источник |
|---|---|
| Бренд | `Product.brand` (колонка «Бренд», idx 1) |
| Линейка | колонка **«Категория»** (idx 2) — сейчас игнорится синком, включить как `Product.line` |
| Модель | `Product.name` (колонка «Название модели», idx 4) |
| Порядок | колонка **«Порядок»** (число, 1 = верх) → `Product.sortOrder` |
| Варианты | `ProductVariant` (цвет/память) |

«Общая категория» (idx 3) — НЕ трогаем (Avito). Линейка идёт отдельным полем.

## 3. Сортировка

- **Модели внутри линейки**: по `sortOrder` ASC (1 = верх = самая новая). Пусто → в конец, стабильно по строке листа. Ярлык «новые сверху» НЕ подписываем — это дефолт.
- **Линейки внутри бренда**: по `min(sortOrder)` их моделей (линейка с моделью №1 идёт первой).
- **Бренды**: порядок из существующего массива популярности (Apple, Samsung, Dyson, Garmin, …, «Прочее» последним).

## 4. Обложки карточек — ФОТО ИЗ ТОВАРОВ (ключевое требование)

Обложка карточки — не отдельный ассет, а **фото реального товара**. Считается на клиенте из `allProducts` (уже in-stock-only), переиспользуя `resolvePhoto` + `isNoPhoto`.

**Карточка МОДЕЛИ:**
```
обложка = главное фото самого товара (resolvePhoto: variant.photos → photoUrl → photos[0])
        → фолбэк no-photo
```

**Карточка ЛИНЕЙКИ (важно — фото самой новой модели в наличии):**
```
обложка линейки = фото самой НОВОЙ модели этой линейки, что В НАЛИЧИИ
  = товар с min(sortOrder), у которого stock>0 И есть реальное фото (не no-photo)
  → фолбэк: любой товар линейки в наличии с фото
  → фолбэк: no-photo плейсхолдер
```

Почему так: `/api/products` отдаёт только in-stock → обложка автоматически «живая» и честная. Если линейка вся распродана — её товаров нет в `allProducts`, линейка не висит пустой. Самая новая ≈ самая дорогая (подтверждено владельцем).

Выкинуть: хардкод-мапу `CATEGORY_IMAGES` и `/public/categories/*.webp` как обложки линеек. Плейсхолдер no-photo оставить, но заполняющий слот целиком (`object-fit:cover`, 100%×100%) — фикс уже в проде.

## 4a. Фон слота фото (согласовано с владельцем)

Слот `.photo` — светлая плитка внутри тёмной карточки (как у Яндекс.Маркета), НЕ тёмный градиент.
- Цвет фона слота: **`#f7f2f0`** (тёплый молочно-бежевый, замерен пипеткой с референса Маркета).
- Слот скруглён (`border-radius:12px`), с отступом от краёв карточки (`margin:10px 10px 0`), `aspect-ratio:1/1`, фото `object-fit:cover`.
- Плейсхолдер-силуэт на светлом фоне — серый (`#9a9a9a`), не неон.
- Товарное фото ложится поверх этого фона; если у фото свой фон — он перекрывает бежевый.

## 5. Наличие на карточках

- Позитивного ярлыка «в наличии» НЕТ. Показана и кликается = в наличии, и так понятно.
- Распроданное (stock=0 || !inStock) `/api/products` и так не отдаёт → **просто не появляется**. Отдельного «погашенного» состояния в проде не рисуем (дефолт — скрыто).
- Опция на будущее (не сейчас): если владелец захочет показывать распроданное — снять гейт и рисовать `.card.oos` (погашена + `pointer-events:none`).

## 6. Геометрия карточки

- Фото-герой сверху: `.photo` aspect 1:1, фото центр/cover.
- Подпись снизу: имя модели/линейки + (для модели) цена «от …».
- Тёмная плитка `#1c1c1e`, радиус 16, ховер — неон-бордер.

## 7. Хлебные крошки

`Главная — Каталог — {Бренд} — {Линейка}`. Клик по бренду → назад на уровень линеек.

## 8. Что решает Phase 2 попутно

Дедупликация: сейчас товар двоится (заведён и под «Категорией», и под «Общей категорией») → два Product'а → 0-копия скрыта, ненулевая видна. Единая иерархия бренд→линейка→модель схлопывает это структурно. NB: владелец параллельно чистит дубли в самом листе — если источник чист, дедупликация в коде минимальна.
