## 🔴 Три противоречия спека с живой таблицей

Спек (`bender_cc_task.md`, зафиксированное решение №2) требует: **«Общая категория» (idx 3)
не трогаем, Avito-safe, линейка — отдельным полем**. На момент написания спека шапка была
`Бренд(1) · Категория(2) · Общая категория(3) · Название модели(4)`.

Живая шапка сейчас: `Бренд(1) · Категория(2) · **Модель**(3) · Название модели(4)`.
«Общей категории» в таблице **нет**.

### 1. «Общая категория» не существует → `category` и `line` разъехаться не могут

Спек хочет `line=2` и `category=3` раздельно. Источника для `category` больше нет.
Шаг 1 уже сделал `category := line`, и в проде `/api/categories` отдаёт линейки.

**План:** `Product.line` заполняем из idx 2, `Product.categoryId` продолжает указывать на
`Category` с тем же именем (= линейка). Сущность `Category` не репокапим — спек соблюдён
в той части, которая ещё выполнима.

### 2. Avito-словарь сломан латентно

`api/server.ts:993` мапит `p.category.name` через `AVITO_CAT`, ключи которого — старые общие
категории (`Телефоны`, `Ноутбуки`, `Планшеты`, `Часы`, `Desktop`, `Умный дом`, `Красота и уход`…).
После Шага 1 там линейки (`iPhone`, `MacBook`, `Apple Watch`) → `AVITO_CAT[catName]`
undefined → `continue` → объявление выпадает.

**Живой регрессии нет:** в проде 0 товаров с `avitoEnabled=true`, фид отдаёт 0 объявлений
(проверено на `/api/avito-feed.xml` и в снапшоте). Но приёмка спека «Avito-фид не изменился»
формально невыполнима: словарь надо перевести на новые значения, иначе при включении
`avitoEnabled` фид молча опустеет.

**Предлагаю:** добавить в `AVITO_CAT` ключи-линейки (`iPhone`→Телефоны/Смартфоны,
`MacBook`→Ноутбуки, `iPad`→Планшеты, `Apple Watch`/`Фитнес-часы`→Часы, `iMac`/`Mac Mini`/
`Mac Studio`→Настольные компьютеры, `AirPods`/`Аудио`→Аудио, …), старые ключи оставить.
~15 строк, без изменения логики.

Отдельно: `api/server.ts:1014` — дефолтный `AVITO_ADDRESS` всё ещё `Павильон 211/1`
(переменной в Railway нет, значит используется именно он). Прошлый PR его не задел.

### 3. Колонка A «Порядок» записана, но заголовок A1 пустой

В A2:A849 лежат числа, A1 = `''`. Спек ждёт заголовок `['Порядок','Order','Sort']`.
Без заголовка маппинг уйдёт в деградацию «порядок строк листа» и весь Шаг 2 окажется
бесполезен.

**Предлагаю:** дописать A1 = `Порядок` (одна ячейка, буквы колонок не сдвигаются),
плюс в коде подстраховка: если заголовок не найден, но idx 0 сплошь числовой — читать idx 0.

### 4. Ключ модели: новая колонка D «Модель» вместо `extractProductName`

Спек: модель = `Product.name` из «Название модели» (idx 4) через `extractProductName()`.
Реальность: появилась явная колонка **«Модель» (idx 3)**, и число «Порядка» привязано
именно к ней (одно число на значение idx 3 — так и записано).

**Предлагаю:** группировать модель по idx 3, `extractProductName` оставить фолбэком на
пустую ячейку. Иначе `sortOrder` придётся переносить на группы, которые с колонкой D
не совпадают.

## Что делаю (после ответов на 4 пункта выше)

### Шаг A — схема (аддитивно, откат = дроп колонок)

```prisma
model Product {
  line      String?  // линейка бренда из «Категория» (idx 2): iPhone, MacBook, Galaxy S
  sortOrder Int      @default(0)  // из «Порядок» (idx 0), 1 = верх/новее; 0 = не задан
  @@index([brand, line])
}
```
`categoryId` / `Category` не трогаем. Миграция аддитивная, существующие строки получают
`line=NULL`, `sortOrder=0` — витрина до первого синка работает как сейчас.

### Шаг B — sync (`lib/sheets-sync.ts`)

- `EXACT_HEADERS` уже отдаёт `line` (idx 2) и `model` (idx 3) — Шаг 1.
- Добавить `sortOrder: ['Порядок','Order','Sort']` + фолбэк idx 0 (числовая колонка).
- `SheetRow`: `+ line`, `+ model`, `+ sortOrder`.
- **Ключ группировки (D2):** `brand|line|model|productName` вместо `productName|category`.
  Это то, что схлопывает дубли структурно (см. §8 design_logic).
- На `Product`: `line = group.line`, `sortOrder = min(group.sortOrder)`; пустая линейка → `'Другое'`.

### Шаг C — API (`api/server.ts`)

`/api/products`: `line` и `sortOrder` в `select` и в payload. `/api/categories`, `/api/brands`,
фильтр `?category=` — без изменений. Плюс правка `AVITO_CAT` и дефолтного адреса (пункт 2).

### Шаг D — webapp (`webapp/index.html`)

Дрилл-даун бренд → линейка → модель по мокапу:
- бренд — горизонтальный чип-фильтр (существующий `BRAND_POPULARITY`, «Прочее» последним);
- линейка — сетка фото-карточек, порядок по `min(sortOrder)` моделей;
- модель — сетка фото-карточек, `sortOrder` ASC, пусто → в конец;
- обложка линейки = фото модели с `min(sortOrder)` в наличии с реальным фото → любой товар
  линейки с фото → no-photo (считается на клиенте из `allProducts`, он уже in-stock-only);
- слот фото: беж `#f7f2f0` под реальные фото, плейсхолдер на всю ячейку без бежа (уже в проде);
- ярлыка «в наличии» нет, распроданное не появляется;
- крошки `Главная — Каталог — {Бренд} — {Линейка}`;
- удалить `CATEGORY_IMAGES` (webapp:1851) и зависимость от `/public/categories/*.webp`.

Магазин Apple-only по факту данных, но ничего не хардкодится — бренды берутся из `allProducts`,
добавление Samsung/Dyson не потребует правок.

### Шаг E — тесты

`line=2`/`model=3`/`sortOrder=0` из живой шапки; «Порядок» пустой → деградация; новый ключ
группировки схлопывает дубли; `/api/products` отдаёт `line`+`sortOrder`.
