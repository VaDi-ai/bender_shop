# Живая проверка портала `k9x2m1.conntest.xyz:8443` — 2026-09-11

Проверено с QA-машины (одна точка, один момент времени). Факт для владельца,
важнее слов.

## Что наблюдалось

| проба | результат |
|---|---|
| DNS | `k9x2m1.conntest.xyz` → `176.126.162.158` (резолвится) |
| TCP :8443 | коннект открывается (SYN/ACK проходит) |
| TLS-handshake | **не завершается** — ClientHello уходит, ответа нет, `time_appconnect=0` |
| `curl https://…:8443/portal/?ref=bs_home` | **timeout ~20 c**, `http_code=000` |
| `openssl s_client` | сертификат не получен (handshake не дошёл) |
| Chrome (CDP, headless) | `net::ERR_TIMED_OUT`, страница «Не удаётся получить доступ к сайту» |

Скрин браузера: `ui/08-portal-cert-probe.png`.
Сырые данные пробы: `ui/cert-probe.json`.

## Вывод (нейтрально)

Это **не** ошибка имени сертификата и не кликабельный TLS-интерстишл. Сервер
принимает TCP-соединение на 8443, но **не отвечает на TLS-рукопожатие** —
HTTPS-запрос зависает и отваливается по таймауту, сертификат ни разу не
предъявляется. Для покупателя тап по промо привёл бы к «крутилке» и ошибке
загрузки.

## Оговорки

Проверка — с одной сети и в один момент. Возможные причины, которые видно только
со стороны владельца: гео/IP-фильтр (наш адрес не в списке), файрвол, TLS ещё не
поднят на 8443, порт слушает не тот сервис. Просьба к владельцу — проверить
портал со своей стороны и подтвердить, что HTTPS на :8443 реально отвечает,
прежде чем включать любую из поверхностей.

## На код это не влияет

PR-1 меняет только «трубопровод»: белый список адресов (портал сохраняется и
отдаётся), выбор способа открытия по хосту (портал → openLink). Достижимость
самого портала — инфраструктура владельца, и ровно ради этого факта стояла
эмпирическая проверка. Обе поверхности остаются `enabled:false` — на витрине
покупателя ничего не меняется.

нет. То есть за час портал поднялся; ранний таймаут был временным (или портал

## Раскатка адресов

После стоп-гейта адреса в `setting_promo_vpn` переставлены на портал через
owner-PUT, **обе поверхности остались `enabled:false`**:
`?ref=bs_home` (кнопка) / `?ref=bs_recs` (карточка). Наружу (`GET /api/promo/vpn`)
по-прежнему `enabled:false` и пустые ссылки — на витрине покупателя ничего не
изменилось. Откат — owner-PUT со значениями из `setting-before.json`.
